libraries :
    aya: A pure-Rust library for loading and interacting with eBPF programs inside the Linux kernel.
    tokio: An asynchronous runtime for Rust used here as the userspace daemon's execution driver.

terms :
    1) eBPF: Extended Berkeley Packet Filter. A technology that allows running sandboxed code inside the Linux kernel without modifying the source or loading kernel modules.
    2) BPF: Berkeley Packet Filter. The original, classic system eBPF was built upon (historically used for tcpdump).
    3) BPFEL: BPF Extension Language (specifically, target 'bpfel-unknown-none' specifies a Little Endian eBPF bytecode target).
    4) BPF-linker: A linker tool used to compile and package eBPF object files into ELF bytecode format.
    5) XDP: eXpress Data Path. A kernel subsystem that allows executing eBPF programs directly at the network driver level.

explanation:
    1) eBPF programs run entirely in the kernel space in a secure, sandboxed environment for high performance.
    2) Classic BPF is a simplified precursor to eBPF. Both execute inside the kernel; however, eBPF is far more powerful, supporting system tracing, maps, helper functions, and JIT compilation.
    3) BPFEL bytecode is compiled and loaded into the kernel using system calls.
    4) BPF-linker is used to link eBPF programs with kernel-specific symbols.
    5) XDP is used for low-latency network filtering before packets enter the standard TCP/IP stack.

main:
    The AI-Firewall project is designed to be a lightweight, self-healing network firewall.
    Instead of writing the entire firewall in a heavy scripting language like Python, we use Rust for its raw speed and efficiency.
    To avoid excessive memory and latency overhead, we do not send every packet to an LLM. Instead, we use simple kernel-level filters and a userspace daemon that handles automatic rule injection.
    
    The project is split into two distinct environments:
        1) Kernel-space (ai-firewall-ebpf): A '#![no_std]' Rust program attached to an XDP hook. It receives packets directly from the network driver before they reach the OS stack.
        2) Userspace (ai-firewall): A daemon running with sudo privileges that loads the compiled eBPF ELF bytecode into the kernel, attaches it to a network interface (e.g. wlan0), and handles rules and telemetry.

    Executing the program:
        $ sudo ./target/debug/ai-firewall --iface wlan0
        When run, this triggers:
        - A 'sys_bpf()' system call to load the bytecode.
        - The Kernel Verifier, which inspects the code for safety (checks bounds, locks, infinite loops).
        - XDP Hooking, which attaches the program to the interface. By default, it returns XDP_PASS, letting normal packets through.
