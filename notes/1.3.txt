libraries :
    clap: A crate used in userspace to parse command-line arguments into a structured Rust configuration.
    env_logger: A standard logging implementation in Rust that prints debug and info statements to the terminal.

terms :
    1) Opt: Command-line arguments struct generated by clap.
    2) opt.iface: The parsed network interface name (defaults to "wlan0").
    3) memlock: Locked memory. Physical RAM pages that are locked so they cannot be swapped to disk.
    4) rlimit: Resource limit. A Linux kernel control mechanism to restrict resource consumption per process.
    5) ELF: Executable and Linkable Format. The standard binary format for object files and executables on Linux.
    6) eBPF Ring Buffer: A lockless circular buffer structure in kernel memory that allows eBPF to send telemetry to userspace with low overhead.

explanation:
    1) Opt defines the CLI arguments structure (e.g. '--iface wlan0').
    2) opt.iface represents the network interface card on which the firewall should be attached.
    3) and 4) BPF maps and programs are pinned in locked kernel memory. By default, Linux imposes strict RLIMIT_MEMLOCK limits. Setting RLIMIT_MEMLOCK to RLIM_INFINITY ensures the loader doesn't fail with OutOfMemory or PermissionDenied errors.
    5) When we build the project, cargo compiles the eBPF code into an ELF binary. The userspace compiler embeds this ELF directly into our userspace program via `include_bytes_aligned!`.
    6) The ring buffer is used to stream packet metadata (events) from kernel-space to userspace asynchronously.

main:
    We write the loader in 'ai-firewall/src/main.rs'.
    The flow of userspace execution is:
        1) Logger setup: Initialize 'env_logger' to handle program output.
        2) Lock memory limit adjustment: Set RLIMIT_MEMLOCK to infinity so we can register eBPF maps.
        3) Bytecode load: Read the embedded eBPF ELF binary into memory.
        4) Kernel logger init: Setup 'EbpfLogger' to read info! strings written by the eBPF program inside the kernel. A background tokio task runs a loop to pull these logs from the trace ring buffer and flush them to stdout.
        5) Program loading: Retrieve the 'ai_firewall' XDP program, load it into the kernel verifier, and attach it to the interface using 'XdpMode::default()'.
        6) Cleanup: The program waits for a SIGINT (Ctrl+C). When the program exits, the Ebpf struct drops, causing Aya to automatically detach the XDP hook and unload the program from the kernel, restoring normal network behavior.
