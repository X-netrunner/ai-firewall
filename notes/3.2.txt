libraries :
    aya::maps::RingBuf: Userspace representation of the eBPF circular ring buffer.
    tokio::io::unix::AsyncFd: An asynchronous wrapper for file descriptors, allowing Tokio to watch the ring buffer's status.
    std::collections::HashMap (StdHashMap): Standard userspace hash table used to track packet counts.

terms :
    1) Padding (_pad): Empty bytes added to a struct to align it to a 4-byte or 8-byte boundary, preventing compiler padding discrepancies.
    2) reserve/submit: Two-step transaction mechanism for writing to a RingBuf. It reserves memory in the buffer first, lets you write directly, and then commits (submits) it.
    3) AsyncFd: Asynchronous File Descriptor. Allows userspace to sleep until the kernel notifies it that data is ready to read in the ring buffer.
    4) Threshold Auto-Block: A rule that automatically blocks an IP in the kernel once its packet frequency crosses a threshold.

explanation:
    1) CPUs read memory more efficiently when variables align to their word size (e.g. 32-bit or 64-bit boundaries). Without padding, different compilers/architectures might insert hidden bytes, breaking shared-memory layout between kernel and userspace.
    2) 'reserve()' guarantees zero-copy writing because it gives us a direct pointer to the buffer slot. Once written, 'submit()' makes it visible to the reader.
    3) 'AsyncFd' allows the userspace program to be extremely lightweight, using no CPU while waiting for traffic events.
    4) Counting is done in userspace to keep kernel code simple and fast. The kernel is purely responsible for filtering and telemetry.
