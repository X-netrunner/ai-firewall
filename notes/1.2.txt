terms:
    1) headers
    2) trace pipe
    3) arp
    4) byte-shifting arrays

explainatons:
    1) Headers are the metadata that describe the packet, including its source and destination IP addresses, protocol type, and other information.
    2) Trace pipe is a mechanism for sending trace events from the kernel to user space.
    3) ARP is the Address Resolution Protocol, used to map IP addresses to MAC addresses on a local network.
    4) Byte-shifting arrays are used to extract specific fields from packet data by shifting and masking the data.

        1) ethernet header : size 14 bytes , contains mac addrress and tells us if the payload is a IPv4 , IPv6 , ARP or others.
        2) ipv4 header : size ATLEAST 20 bytes , contains the source and destination ip address , protocol type , and other information.
        3) tcp/udp header : size ATLEAST 20 bytes , port numbers and connection flags.

    Something very impoprt to know is that the linux kernal verifier to extremely strict . before letting your code run , it will check every single memeory access to ensure you will  never read out-of-bounds memory . for example if you try to  read 14 bytes into the packet data without explicitly proving to rust/eBPF that data + 14 <= data_end()  the kernel will reject your code for sure.
