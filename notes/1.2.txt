libraries :
    network-types: A crate containing low-level network protocol structure definitions (like EthHdr, Ipv4Hdr, TcpHdr) used to parse packets in no_std Rust.

terms :
    1) Headers: Structured metadata prepended to packet payloads (e.g. Ethernet Header, IP Header) containing routing, protocol, and length information.
    2) Trace Pipe: A debug file mechanism (`/sys/kernel/tracing/trace_pipe`) used to read kernel-space logs written via bpf_trace_printk or aya_log.
    3) ARP: Address Resolution Protocol. Used to map IP addresses to MAC hardware addresses on a local network.
    4) Byte-shifting arrays: Hand-written byte operations (shifting and masking) used to parse packet fields before structs like network-types were used.

explanation:
    1) Headers encapsulate the packet payload at different network layers (Layer 2, Layer 3, Layer 4).
    2) The trace pipe is an easy way to verify what the kernel eBPF program is doing without setting up maps.
    3) ARP packets are layer 2 broadcasts. Currently, the firewall only intercepts and parses IPv4 headers, letting other types (like ARP) pass through automatically.
    4) Hand-rolled byte-shifting is error-prone. Using a well-defined layout struct from the network-types crate is clean and verifier-safe.

main:
    We implement packet dissection in 'ai-firewall-ebpf/src/main.rs'.
    When a packet hits the network interface, eBPF provides two memory pointers:
        1) ctx.data(): A pointer to the start of the raw packet bytes.
        2) ctx.data_end(): A pointer to the end of the raw packet bytes.

    Packets are layered sequentially:
        1) Ethernet Header (14 bytes): Contains source/destination MAC addresses and identifies the payload protocol (e.g. IPv4, IPv6, ARP).
        2) IPv4 Header (minimum 20 bytes): Contains source/destination IP addresses, Layer 4 protocol (TCP/UDP), and packet length.
        3) TCP/UDP Header: Contains source/destination port numbers and flags.

    Strict Kernel Verification:
        The kernel verifier enforces memory safety. You cannot read or cast packet data without explicitly proving that the read fits within the packet boundaries:
        e.g., 'start + EthHdr::LEN <= end' must be checked before accessing fields in the Ethernet header. Otherwise, the kernel throws a verification error and rejects the program.

    Parsing Details:
        - '#![no_std]': Required because eBPF runs inside a restricted virtual machine in the kernel with no OS standard library allocator.
        - Pointer casting: Using 'unsafe { &*(pointer as *const Struct) }' lets us read raw packet bytes as typed structs.
        - Endianness conversion: Network headers are formatted in Big Endian, while x86 CPUs are Little Endian. We translate values using 'u16::from_be()' or 'u32::from_be()' so they can be processed correctly by the CPU.
